# Release and adoption scope

Albert authorised publication of a private base policy, adoption in My EA, and
subsequent evidence collection and a maintained dashboard for combined trial.
Existing rules remain mandatory. Implementation status is not policy applicability.

The policy release preserves 38 stable rule IDs and the accepted compressed routing.
It excludes presentation rules, personal source snapshots and classified content.
The shared source is separated from per-repository configuration. Bundle integrity
depends on an independently trusted commit and manifest digest.

My EA adoption must preserve existing architecture, project tests, independent
reviews, documentation governance, unrelated local work and human merge. It must
explicitly reconcile compact specifications with the existing contract format.
No global personal discipline is rewritten. New repositories use the same pinned
adoption pattern and keep their own project adapters/additions.

Evidence and dashboard acceptance: show all applicable rules, not just the
automated subset; distinguish unknown/missing, declared, authentic and independently
reviewed evidence; bind records to revisions and policy versions; surface collector
errors/freshness, exceptions, device-test debt and release/outcome debt. Never use
green metadata presence as a whole-change compliance verdict. Keep fixtures
separate from real records. No raw prompts, logs, comments or private app data are
required. Reviewer handles are identifying metadata used only for provenance.

The private GitHub repository's plan currently prevents native required-check
protection. That limitation is shown explicitly until the actual boundary is
available and tested. A prepared adoption PR or a manual operating rule is not
technical enforcement. Publication does not grant an agent merge/distribution rights.
